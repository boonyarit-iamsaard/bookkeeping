1. Give each feature its cached-read lifecycle

Strong ports & adapters
Files

core/api/queries.ts · features/transactions/transaction-reads.ts · features/dashboard/dashboard-queries.ts · routes/_app/{transactions,wallets,categories,dashboard}/*.tsx

Problem
Read adapters are centralized, while cache effects live elsewhere; category writes can leave cached transaction views stale because those responses embed category data.
Solution
Keep generic HTTP mechanics internal, and concentrate each feature’s reads, cache effects, and projections in one deep module.
Benefits
  • locality: cache rules concentrate
  • leverage: one feature interface
  • tests cross the same seam
  • path knowledge stops leaking

2. Deepen money interpretation and display

Worth exploring in-process
Files

features/wallets/components/money.tsx · features/transactions/components/signed-money.tsx · features/transactions/{editable-transaction,linked-expense,wallet-options}.ts · features/dashboard/components/financial-report.tsx

Problem
Dashboard and transaction modules import money interpretation from the wallet feature; the ownership seam leaks across ten call sites.
Solution
Concentrate wire parsing, exact-value conversion, editable formatting, signs, and accessible display in one shared deep module.
Benefits
  • locality: money rules concentrate
  • leverage: every money view
  • one in-process test surface
  • wallet seam stops leaking

3. Deepen transaction screen preparation

Worth exploring ports & adapters
Files

routes/_app/transactions/{new,$transactionId_.refund,$transactionId_.edit}.tsx · features/transactions/{editable-transaction,linked-expense,wallet-options}.ts · components/transaction-form.tsx

Problem
New, refund, and correction routes each coordinate remote reads and pure transforms; bugs can hide in how individually tested helpers are called.
Solution
Concentrate conditional reads, retained-wallet policy, refund facts, and form-ready shaping in one transaction preparation module.
Benefits
  • locality: preparation concentrates
  • leverage: three transaction modes
  • routes cross one seam
  • tests cover helper composition
ADR note: preserve ADR 0005: the browser consumes refund allowance facts and may mirror hints; it does not become the author of the refund allowance rule.

4. Deepen signed-in session transitions

Speculative mock
Files

core/auth/session.ts · core/api/unauthenticated-middleware.ts · main.tsx · features/auth/complete-provisioning.ts · hooks/use-{sign-in,sign-up}-form.ts · components/account-menu.tsx

Problem
Five callers know when to provision, clear all cached reads, and navigate after authentication changes.
Solution
Concentrate signed-in session transition policy behind one module while keeping Better Auth as the external adapter.
Benefits
  • locality: ordering in one place
  • leverage: every session change
  • mock adapter tests transitions
  • callers lose cache knowledge
ADR note: preserve ADR 0003/0006: Hono remains the sole backend and Better Auth remains the authentication implementation. This candidate only deepens client-side transition policy.

Top recommendation

Give each feature its cached-read lifecycle

It removes knowledge shared by the most callers, replaces path-prefix cache coupling with feature locality, and creates one test surface for reads, projections, and cache effects without reopening any ADR.

Outcome · 23 September 2026

Grilled against the code before acting. The client uses TanStack Query's default staleTime: 0, so a missed invalidation shows previous data briefly on the next visit rather than leaving it wrong; that is accepted.

  • 1. Cached reads · replaced. No per-feature cache modules and no split of queries.ts. Every write calls one refreshAfterWrite that refreshes all reads except the session; a delete retires its own reads. Recorded in docs/code-conventions.md under “Cached reads”.
  • 2. Money · reduced to a move. The depth already lives in @bookkeeping/domain/money. Wire parsing moved to core/api/money.ts, Money to shared/components/money.tsx with a sign prop, and SignedMoney was deleted.
  • 3. Transaction preparation · reduced. Only the repeated owned-transaction lookup was extracted (loadOwnedTransaction); the edit loader's two conditional reads do not earn a module.
  • 4. Session transitions · dropped. resetSessionCache already concentrates the clearing; no known bug justifies a mocked seam.
