## Agent Brief

**Category:** bug
**Summary:** The shared `Button` moves 1px down while pressed, breaching the Motion rule's three feedback moments.

**Current behavior:**
The shared `Button`'s base variant class translates the button 1px down on
`:active` (except when it opens a popup) and animates the move through
`transition-all`. Nothing turns it off under `prefers-reduced-motion`. Every
button in the app nudges on press, on phone and desktop.

**Desired behavior:**
A pressed button stays where it is. The spec's Motion rule allows only the
indicator slide, the arrival fade and the sheet slide, so remove the nudge
rather than guarding it with `motion-reduce`. Colour, ring and opacity
feedback for hover, focus, press and disabled stay as they are.

**Key interfaces:**

- The shared `Button` component's base variant class string (the `cva` base
  used by every variant and size): drop the pressed translate, and narrow the
  transition so it no longer covers `transform`.

**Acceptance criteria:**

- [ ] No `Button` variant carries a pressed-state translate.
- [ ] The base class does not transition `transform` (e.g. `transition-colors`
      or an explicit property list in place of `transition-all`, keeping any
      ring or shadow transitions the design needs).
- [ ] `pnpm run ci` passes.

**Out of scope:**

- The indicator slide, arrival fade and sheet slide.
- Popover, Select and menu motion (closed in 16) and the delete confirmation
  (closed in 17).
- Touch-target sizes and other polish in 19.
