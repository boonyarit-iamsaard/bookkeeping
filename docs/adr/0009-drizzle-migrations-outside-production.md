# Drizzle migrations replace `db:push` everywhere but production

Until 2026-09-27 every database, from tests to the Railway trial, got its
schema from `drizzle-kit push`, because the domain model was unsettled. Real
data now approaches, and it needs a schema history that can rebuild production
from nothing. We switch to SQL migrations generated by `drizzle-kit generate`,
committed to the database package, and applied through one exported migrator
function in tests, CI, and local development. Migrations are forward-only: a
bad migration is fixed by a newer one, and lost data comes back from backups.
Applying migrations to production is deliberately left out and decided with
the rest of real-data readiness; until then the trial database keeps receiving
`db:push` by hand and is wiped before the real ledger starts.

## Considered options

- Atlas or graphile-migrate: rejected. Both bring stronger linting, but they
  add a second source of truth for the schema beside the Drizzle tables the
  code already types against.
- Hand-written down scripts: rejected. Drizzle never runs them, so they would
  be untested code that nobody could trust on the day it mattered.
- Keeping `db:push --force` for test databases: rejected. Tests would then
  never apply the migrations, so a broken migration would reach the first real
  deploy unnoticed.
- Switching production at the same time: rejected for now. Where migrations
  run depends on the hosting review, and it belongs with backups and the
  trial-data wipe.

## Consequences

- `db:push` survives only for local experiments on a throwaway database; a
  schema change is generated as a migration before it is committed.
- Until production applies migrations, committed migrations may be squashed.
  The production step starts by wiping the trial database and squashing to one
  baseline; from then on committed migrations are immutable.
- The Drizzle 0.x migrator orders by its journal and skips a migration older
  than the last one applied, so migrations merged out of order can be missed.
  One developer makes this unlikely; Drizzle v1's folder format removes it.
- Naming, the rename hand-off, and the local reset live in
  `docs/code-conventions.md`, not here.
